# V1 数据库迁移

这份迁移只准备结构，不填入账号、密钥、群人数或考核日期。工作台首次登录时才创建该账号的种子数据。

## 方法一：控制台迁移（推荐首次部署）

1. 在选定 CloudBase 环境的文档数据库创建集合 `campus_workspaces`。
2. `_id` 使用内置唯一索引，不需要另建业务索引。
3. 在集合“数据权限 → 自定义规则”中应用 `security-rules.json` 并保存。
4. 在云存储自定义权限中应用 `storage-rules.json`。规则限定邮箱账号 UID 的创建者权限，不适用于本版未提供的微信登录。
5. 用控制台规则测试器验证匿名拒绝、本人允许、其他账号拒绝；验证创建和更新均受限制。安全规则中的 `doc` 与 `resource` 是 CloudBase 内建变量。

机器可读的结构定义见 `migrations/001-workspace.json`。此版本不更改已有数据、集合或权限；重复执行时保留已有集合。

## 方法二：部署终端结构迁移

安装项目开发依赖后，在受控部署终端通过环境变量注入：

- `CLOUDBASE_ENV_ID`：目标环境标识。
- `TENCENTCLOUD_SECRETID`、`TENCENTCLOUD_SECRETKEY`：有目标环境数据库权限的管理端凭据。
- 使用临时凭据时额外注入 `TENCENTCLOUD_SESSIONTOKEN`。

不要放在 `.env.local` 的 `VITE_*` 中，不要提交到代码仓库或粘贴到聊天。脚本不打印凭据、请求正文或原始异常响应。

```powershell
npm run db:migrate
```

脚本使用管理端 SDK 的 `createCollection`，检测到已存在集合会保留。成功后仍须在控制台应用两份权限规则，脚本不会开放默认权限。运行后移除部署终端不再需要的管理凭据。

## 快照结构

| 字段 | 内容 |
| --- | --- |
| `_id` | 当前认证账号 UID，一个账号一个快照 |
| `_openid` | 同一认证 UID，作为权限所有者 |
| `revision` | 从 0 开始，保存时带旧值做条件更新并递增 |
| `payload` | JSON 字符串，包含 schemaVersion、rows、updatedAt、lastImportAt |
| `updatedAt` | ISO 8601 UTC 保存时间 |

一条文档保存多个关联实体，允许在单次原子更新中同时删除父记录和清空引用。查询同时限定 `_id` 与 `_openid`，更新另限定旧 `revision`。若更新条数不是 1，界面报告冲突。

V1 限额为 3,000 行、JSON 750 KiB，预留服务端文档体积开销；长期扩展为多集合时，需新增 schemaVersion=2 迁移并对关系操作提供事务。此目录未包含虚构的 SQL，因为实际使用 CloudBase 文档数据库。

## 发布前必须验证

- 未登录时读取、创建、修改和下载均拒绝。
- 账号 A 可以读取和修改自己的快照，不能读取或修改账号 B 的快照。
- 账号 B 不能伪造 A 的文档标识和 owner 来写入 A 的记录。
- A 的两个设备同时打开时，先保存的成功，旧版本的保存被拒绝。
- 手机用同一账号读取刚刚在电脑保存的记录。
- 上传附件后，本人可查看，另一账号与匿名访问者无法直接下载。

云端环境尚未提供，以上实际权限验收由部署时执行。前端校验提升日常数据质量，不能替代服务端权限规则。
