# 腾讯云 AI 校园大使个人运营工作台 V1.0

GPT 负责工作台开发与维护。网页由 Vercel 托管，公开数据保存在 GitHub 仓库；不需要 WorkBuddy 或腾讯云部署连接。

## 本地启动

要求 Node.js 22.12 或更新版本（本次使用 Node.js 24.15.0）。在本目录打开终端：

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev -- --port 5173
```

打开 `http://127.0.0.1:5173/`。默认 `VITE_DATA_MODE=local`，无账号、无云端凭据也能使用全部核心记录功能。本地数据保存在该地址对应浏览器的 localStorage 中；切换端口、浏览器、设备或清理站点数据会进入不同工作区。不要用双击 `dist/index.html` 的方式运行。

```powershell
npm test
npm run build
npm run preview -- --port 4173
```

## GitHub 公共数据与 Vercel 上线

工作台入口：[https://campus-ambassador-console.vercel.app/](https://campus-ambassador-console.vercel.app/)。网页由 Vercel 托管，运营快照保存在同一个公开仓库的 `data/workspace.json`。任何人都可以读取网页和当前数据。仓库源代码、数据文件和完整 Git 提交历史也公开，修改或删除记录不会抹去旧提交中的内容。请只录入适合公开的信息，不要放入个人联系方式、账号口令、企业微信凭据或私密附件。

数据读取使用 GitHub 的公开文件地址，不需要 WorkBuddy CloudBase 连接器、腾讯云账号或访问令牌。编辑与 GPT 写入需要由仓库所有者在工作台连接一个 GitHub 细粒度个人存取令牌：资源所有者选择仓库所有者，只允许访问这个工作台仓库，并仅授予 `Contents: Read and write`。网页会核对令牌对应的 GitHub 账号是否为仓库所有者。令牌只放在当前浏览器标签页的 `sessionStorage` 中；关闭标签页后需要重新连接。它不会写进仓库、网页构建配置或交接文件，且只发送到 `api.github.com`。请使用 HTTPS 并设置令牌过期时间。

工作台每次保存都会更新 `data/workspace.json` 并生成公开 Git 提交；所有设备读取同一份数据。版本号和 GitHub 文件 SHA 会阻止旧版本覆盖；遇到冲突时重新读取再修改。网页从 GitHub 公开文件地址读取数据，所以记录保存后无需重新构建网页。当前 Vercel 项目没有关联 GitHub 自动构建；源码更新时由 GPT 重新构建并发布到同一 Vercel 项目，稳定网址不变。

公开数据快照由 `npm run data:seed` 从 `seedWorkspace()` 生成；脚本检测到文件已存在时会拒绝覆盖。当前生产构建使用 GitHub 数据模式并直接发布到 Vercel，不需要 GitHub Actions 工作流或 WorkBuddy 部署连接。Vercel 生产站点公开可读，预览部署保留登录保护。

本地预览 GitHub 模式时，将以下设置写入 `.env.local` 后运行 `npm run dev`：

```dotenv
VITE_DATA_MODE=github
VITE_GITHUB_REPOSITORY=owner/repository
VITE_GITHUB_BRANCH=main
VITE_GITHUB_DATA_PATH=data/workspace.json
VITE_GITHUB_EDITOR_LOGIN=owner
VITE_BASE_PATH=/
```

`VITE_*` 配置会出现在公开网页代码中，只能填写仓库名、分支、路径和公开的 GitHub 登录名。GitHub 令牌绝不能写入 `VITE_*`、源码或 Vercel 环境变量。GitHub 模式使用证据链接；附件上传仍需 CloudBase 存储，不能把私密文件放进公开仓库。

GitHub 模式适用于个人、低频编辑，工作区仍限制 3,000 条记录和 750 KiB 快照。频繁并发、多用户协作或需要隐私隔离时应使用受保护的数据库。

浏览器验收需另开终端保持开发服务运行。使用独立的验收浏览器工作区，初始数据应为默认的 8 条记录：

预览浏览器配置使用原生窗口尺寸（`viewport: null`）。检查脚本会另建独立测试上下文，改变测试尺寸和数据时不会调整日常预览窗口或修改其中的记录。

```powershell
npm run browser:open
npm run test:browser
```

若本机没有可用的浏览器，先运行 `npx playwright-cli install-browser`。浏览器检查会临时创建与删除带“验收临时”前缀的记录；请勿在已有正式数据的浏览器工作区运行。截图与测试下载保存到 `output/playwright/`，不会被提交。

## 已实现的功能

视觉修订：桌面任务卡片合并标题与摘要信息，默认 3 条任务可同时完整显示；日期筛选按需展开。窗口宽度不超过 1100px 时导航改为抽屉，任务区按实际可用内容宽度重排，支持半屏、窄面板和手机；全站页尾保留留白。页面切换回到顶部。

| 页面 | 功能 |
| --- | --- |
| 运营总览 | 四项动态指标、渠道图表、任务待办、核验清单、数据连接状态 |
| 拉新管理 | 渠道、方向、确切值/严格上界/未知值、个人/团队/未明确归属 |
| 社群运营 | 社群档案与运营记录两个视图、实测成员数、关联活动 |
| 活动与内容 | 活动和内容两个视图，关联社群、分类、日期、状态与证据 |
| 任务中心 | 任务看板和列表、优先级、截止日期、关联记录与状态更新 |
| 成果与复盘 | 成果/复盘记录、证据链接、自动汇总 Markdown 复盘文档 |

所有记录支持新增、编辑、查看、删除、搜索、状态/来源/记录日期筛选、排序，以及 CSV 导出；拉新另支持方向筛选。JSON 完整备份和合并导入保留关联关系。CSV 带 UTF-8 BOM，转义换行与引号，并防止公式注入。移动端使用抽屉导航和可横向滚动的表格，任务看板改为纵向排列。

本项目使用 React 19 + TypeScript + Vite + Tailwind CSS 4 + Radix Dialog + Lucide + Recharts。对话框基于与 shadcn 相同的 Radix 原语定制；没有生成完整的 shadcn 组件库。

## 初始数据与统计口径

| 用户提供的信息 | 系统保存方式 |
| --- | --- |
| 比赛群 5 人 | 确切值 5，已确认，成果归属未明确 |
| 晚自习走班不足 3 人，待核实 | 严格小于 3，待核实；3 为不含的上界 |
| 熟人邀请 31 人 | 确切值 31，团队共同成果 |
| 社团群推广人数未量化 | `count=null`，未量化 |
| 成员退出 4 人 | 确切值 4，方向为退出，所属群与日期留空 |

另有 3 条明确标记为“系统建议”的资料完善任务，不代表已经执行。没有预填实际群名、群总人数、活动成果或考核日期。

- “已确认渠道新增记录”只加总已确认、确切值、方向新增且非团队的渠道记录；它不是去重人数，也不是个人独立成果。
- “团队共同邀请记录”单列团队已确认确切值，不并入非团队指标。
- “成员退出记录”单列，不用已有渠道记录减退出数推算群净增长。
- “群成员数合计”仅在至少一个社群存在、且所有社群均有已确认确切值时显示；群间仍可能存在重复成员，不能称为去重总人数。
- 图表只使用已确认确切值。未知值不按 0 处理，严格上界不当作实数；确切值 0 则有效。
- “逾期”仅判断实际填写截止日期的未完成/未取消任务，按北京时间比较。
- 来源“用户提供”表示用户在本次需求中确认的数据，尚未自动与企业微信记录交叉验证。

## 企业微信 CLI：后续真实数据来源

授权凭据始终由本机 `wecom-cli` 管理，不复制到网页、数据库、环境模板或部署包。

如果 CLI 尚未安装，先运行 `npm install -g @wecom/cli`；检查提示未授权时，在本机运行 `wecom-cli auth init --noninteractive`，由用户扫码授权。已安装且已授权时无需重复初始化。

```powershell
npm run wecom:check
npm run wecom:pull -- --days 7 --list
npm run wecom:pull -- --days 7 --group "实际群名"
```

在“数据中心 → 导入与核验”选择默认生成的 `.wecom/candidates.json`，查看新增和冲突数，再确认合并。可以用 `--out` 指定其他输出路径。Windows 默认查找全局 npm 安装的 CLI；自定义安装位置时用 `WECOM_CLI_ENTRY` 指向 `@wecom/cli/bin/wecom.js`。

脚本只执行版本检查、授权状态检查、群列表与消息读取。不会发送消息、改群、改企业微信文档或写回原系统。读取时精确匹配指定群名，同名多群会停止；完整分页之后才写候选文件，超过 100 页、循环游标、接口错误都会停止。

当前 CLI 接口只支持最近 7 天、当前授权可读范围内的会话和消息。群消息接口不提供成员总人数、成员新增、退出人数或完整外部微信群数据；这些指标仍需企业微信中实际可读的成员/统计来源，或用户核验，不能由消息数推断。未来可在同一接入层增加已确定的企业微信文档、表格来源。

候选文件包含一个群档案与按日归纳的消息观察记录，默认“待核实”；每条每日观察仅保留最多 5 条、每条最多 350 字的文本摘录及窗口消息数。数据含运营信息，请将候选文件和完整备份保存在个人受控目录。网页始终把外部文本作为普通文本渲染。

来源键采用“群名摘要 + 日期”；同一文件重复导入会跳过相同记录，新抓取版本可能出现冲突，默认保留本地，勾选更新后才覆盖。由于接口没有稳定消息编号，本版没有把单条消息伪装成成员或拉新事实。群改名会产生新来源键，需手动核验关联。

## CloudBase 配置与多设备同步

1. 在腾讯云 CloudBase 创建环境，启用文档型数据库、云存储及静态网站托管，记录环境标识。
2. 在身份认证中启用邮箱/密码登录，为自己创建或注册一个经过验证的邮箱账号。本版不开放自助注册界面。
3. 将本地与正式站点域名加入认证安全域名；本地测试端口也要按控制台要求加入。配置云存储允许的站点域名。
4. 按 `database/README.md` 完成结构迁移，应用数据库和云存储的个人权限规则，使用规则测试器测试匿名、本人和其他账号。
5. 修改 `.env.local`：

```dotenv
VITE_DATA_MODE=cloudbase
VITE_CLOUDBASE_ENV_ID=你的实际环境标识
```

6. 重启开发服务，或重新执行 `npm run build`，然后登录邮箱账号。

`VITE_*` 会公开进入浏览器构建产物，只能存非机密环境标识和模式选择。不要放腾讯云 SecretId/SecretKey、企业微信令牌或登录密码。云模式缺少环境标识时构建会失败，不会悄悄降级成本地模式。

每个邮箱账号对应独立工作区，首次登录创建真实初始数据。同一账号多设备访问相同云端文档；每次保存使用 `revision` 条件更新。页面每 30 秒检查新版本，发现后提示重新读取；不会静默覆盖正在编辑的草稿。遇到版本冲突，先保留草稿、导出当前完整备份，再重新读取并重试。本地模式也有多窗口冲突保护。

本地数据不会自动覆盖云端。切换前从本地导出完整 JSON；登录云端后在数据中心预览合并，逐条确认冲突。JSON 导入是合并，不会自动删除备份中不存在的记录。

附件上传仅在云模式启用，最大 10 MB。保存的是私有文件引用，查看时申请临时下载链接。替换、取消编辑或删除记录不会自动删除存储对象，需在控制台清理不再使用的文件。

**验收边界：**由于本次没有 CloudBase 环境和登录凭据，已验证云端适配器的模拟契约与云模式编译，但真实登录、数据库安全规则、附件上传和双设备同步需在部署环境实测。详见 `database/README.md`。

## GPT 部署后的操作能力

工作区已提供可直接操作的表单和稳定的 `window.campusWorkbench` 浏览器接口，可读取、新增、更新、删除、导入导出及修改任务状态。公开访问只读；GitHub 模式下，写入还要求当前标签页已连接仓库所有者的令牌。所有写入沿用统一校验与版本保护，并可先预览、后提交、再回读。正在编辑的草稿会阻止外部写入。

支持 WebMCP 的浏览器会自动注册 5 个 campus_* 工具；普通浏览器可通过页面或稳定接口操作。GitHub 模式编辑前先在当前标签页连接细粒度令牌；关闭页面后不会后台运行，重新打开需再次连接。具体调用和上线验收见 `docs/GPT-CONTROL.md`。当前已实测浏览器接口，WebMCP 原生发现与调用待支持该能力的环境验收。

## 数据模型与目录

`src/domain.ts` 为运行时 Zod Schema 与统计口径的唯一来源。`Workspace.schemaVersion=1`，`rows` 为统一记录集合，`kind` 区分实体。关联关系：

```text
社群 communities ← groupId ← 拉新 / 运营 / 活动 / 内容 / 任务 / 复盘
活动 activities  ← activityId ← 拉新 / 运营 / 内容 / 任务 / 复盘
任意记录         ← relatedId ← 任务 / 复盘
```

删除一条记录会清空其他记录指向它的引用，保留历史子记录；导入和保存均验证关系，拒绝悬空引用、重复标识和重复来源。本地与 CloudBase 模式使用各自的版本化工作区；GitHub 模式使用一个公开版本化快照。适合 V1 个人运营管理：最多 3,000 条记录、JSON 750 KiB。超限会阻止保存并提示归档；后续规模扩大时可迁移为独立实体集合与分页查询。它不是多人协作或企业级成员 CRM。

```text
src/                  界面、数据模型、本地 / CloudBase / GitHub 持久化适配器
scripts/wecom-sync.mjs 企业微信只读抓取与候选归纳
scripts/create-seed-snapshot.mjs 从真实初始数据生成公开仓库快照
data/workspace.json    GitHub 模式读取和更新的公开运营快照
scripts/browser-smoke.js 真实浏览器流程验收
tests/                统计、关系、导入、存储冲突和 CLI 离线测试
database/             结构迁移、权限规则与执行说明
docs/GPT-CONTROL.md   GPT 网页操作说明
docs/TEST-REPORT.md    本次验证结果与限制
dist/                 GitHub 数据模式生产构建；源码更新后由 GPT 发布到 Vercel
```

## 常见问题

- 本地数据损坏或存储空间不足：界面会保留原内容并显示错误，不自动清空。可通过浏览器开发工具保留 `campus-console:workspace:v1` 的原始值，再恢复已经导出的备份。不要先清理站点数据。
- 刷新后看不到另一个窗口修改：先保留自己的草稿，点顶部重新读取；直接重复提交旧版本会被拒绝。
- 日期筛选后记录减少：未填写记录日期的记录会排除，清除日期筛选可重新显示。
- 云端无法读取：检查登录状态、环境标识、安全域名、集合是否存在及规则中 owner 条件。不要临时把规则改为所有人可读写。
- 企业微信读不到指定群：使用 `--list` 查看本次授权范围内且近 7 天有消息的群，使用精确名称；没有返回不代表群不存在。
- 依赖安全：锁文件已纳入交付。管理端迁移 SDK 使用 `4.2.1`，其 axios 旧锁定依赖通过 `overrides` 升级至 `0.34.0`。实际迁移仍需部署端验证；前端不导入管理端 SDK。

官方参考：[CloudBase 数据库规则](https://docs.cloudbase.net/database/security-rules)、[云存储规则](https://docs.cloudbase.net/storage/security-rules)、[安全规则示例](https://docs.cloudbase.net/rule/rule-example)。
